# Intents HR Platform

This repository contains the initial ASP.NET Core .NET 8 Web API setup for an HR candidate management system.

## Current Step

This first implementation step creates the clean project foundation and the database model layer for managing candidates and their skills.

The goal of this commit is not to build API endpoints yet, but to prepare the application structure so future features can be added on top of a clear Entity Framework Core data model.

## What Was Added

- A new ASP.NET Core .NET 8 Web API project structure
- Entity models inside the `Models` folder:
  - `Candidate`
  - `Skill`
  - `CandidateSkill`
- `ApplicationDbContext` inside the `Data` folder
- PostgreSQL support through `Npgsql.EntityFrameworkCore.PostgreSQL`
- DbContext registration in `Program.cs`
- PostgreSQL connection string configuration in `appsettings.json`

## Database Design

The system currently supports:

- Candidates with full name, date of birth, contact number, and email
- Skills with a unique name
- A many-to-many relationship between candidates and skills through `CandidateSkill`

The database configuration also enforces:

- Unique candidate email addresses
- Unique skill names
- No duplicate candidate-skill pairs

## Why Controllers And Services Are Not Added Yet

Controllers and services are intentionally left out in this step.

This keeps the first commit focused on the domain model and database structure only. API endpoints, business logic, validation flows, and service abstractions can be added in later steps once the core data model is stable.

## Generated Project Files

Files such as `Program.cs`, `.csproj`, `Properties/launchSettings.json`, `appsettings.json`, and the `.http` file are standard files generated by the ASP.NET Core Web API template.

Folders such as `bin/` and `obj/` are generated during restore/build and are ignored by Git.
